## 2. 产品概述

### 2.1 产品名称与定位

**产品名称：** 可视化设备状态管理系统

**产品定位：** 旨在为企业或个人提供一个直观、高效的设备状态可视化管理平台，通过平面图拖拽式布局，实时监控各类设备的运行状态和数据，提升管理效率和决策质量。

### 2.2 产品愿景与使命

**产品愿景：** 成为设备管理领域领先的可视化解决方案提供商，赋能用户实现智能化、精细化的设备运营与维护。

**产品使命：** 通过创新的可视化技术和友好的交互体验，简化设备管理复杂性，帮助用户实时掌握设备健康状况，预防故障，优化资源配置，从而提升整体运营效率和安全性。

### 2.3 价值主张与独特卖点 (USP)

**核心价值主张：**

1.  **直观可视化：** 将抽象的设备数据具象化到平面图上，一目了然地掌握设备分布与状态。
2.  **实时监控：** 提供设备温度、电力等关键指标的实时数据，及时发现异常。
3.  **灵活配置：** 用户可自定义上传平面图，并通过拖拽方式自由添加和管理设备。
4.  **提升效率：** 简化设备巡检和故障排查流程，降低人工成本，提高管理效率。

**独特卖点 (USP)：**

-   **“所见即所得”的平面图拖拽式设备布局：** 极大地降低了用户配置和管理设备的门槛，使得非技术人员也能轻松搭建和维护可视化监控界面。
-   **高度可定制化的数据展示：** 支持用户根据需求配置不同设备的显示数据和预警规则。

### 2.4 目标平台列表

-   Web (桌面/移动响应式) - 基于Next.js和TypeScript开发。

### 2.5 产品核心假设

1.  用户对设备可视化管理有强烈需求，且现有解决方案操作复杂或功能不足。
2.  用户愿意投入时间上传平面图并配置设备信息。
3.  设备数据能够通过现有接口或未来扩展方式接入系统。
4.  Next.js和TypeScript技术栈能够满足产品的性能和扩展性要求。

## 3. 用户故事/功能列表

### 3.1 核心功能

*   **平面图管理：**
    *   用户可以上传自定义平面图（如楼层平面图、园区地图等）。
    *   用户可以在平面图上进行缩放、平移操作。
*   **设备拖拽与配置：**
    *   用户可以从设备库中选择设备图标，拖拽到平面图的任意位置。
    *   用户可以对拖拽到平面图上的设备进行位置调整、删除。
    *   用户可以点击设备图标，弹出配置面板，配置设备名称、设备类型、关联数据源等信息。
*   **设备状态可视化：**
    *   设备在平面图上通过颜色变化、图标闪烁等方式直观展示其当前状态（如正常、异常、离线）。
    *   鼠标悬停在设备图标上时，显示关键状态数据（如温度值、电力消耗等）。
*   **设备数据展示：**
    *   点击设备图标，进入设备详情页，展示设备的实时数据、历史数据曲线图。
    *   设备详情页应包含设备基本信息、运行参数、告警记录等。
*   **报警与通知：**
    *   系统支持设置设备关键指标的阈值报警规则。
    *   当设备状态异常或数据超出阈值时，系统应通过界面弹窗、消息通知等方式提醒用户。
*   **用户与权限管理：**
    *   支持多用户登录，不同用户拥有不同的角色和权限。
    *   管理员可以管理用户账号、分配角色和权限。

### 3.2 非功能性需求

*   **性能要求：**
    *   **并发用户：** 初期支持至少50个并发用户，未来可扩展至数百甚至上千。
    *   **数据刷新频率：** 关键设备状态数据刷新频率应在5秒以内，一般数据刷新频率在30秒以内。
    *   **响应时间：** 页面加载时间不超过3秒，核心操作（如设备拖拽、配置保存）响应时间不超过1秒。
*   **安全性要求：**
    *   **用户认证：** 采用基于Token的认证机制（如JWT），支持用户名/密码登录。
    *   **数据传输：** 所有敏感数据传输必须采用HTTPS加密。
    *   **权限控制：** 实现基于角色的访问控制（RBAC），不同角色拥有不同的功能操作和数据查看权限。
    *   **数据隔离：** 若未来支持多租户，需确保租户间数据严格隔离。
*   **可扩展性要求：**
    *   **设备类型：** 系统架构应支持未来接入更多种类的设备和数据协议。
    *   **功能模块：** 模块化设计，便于未来新增功能模块（如报表中心、AI预测等）。
    *   **多租户：** 预留多租户支持的扩展能力。
*   **兼容性要求：**
    *   **浏览器：** 兼容主流现代浏览器，包括Chrome、Firefox、Edge、Safari的最新两个版本。
    *   **操作系统：** Web端无特定操作系统要求，桌面端（如未来考虑）需兼容Windows和macOS。
    *   **屏幕适配：** 支持响应式设计，适配不同分辨率的桌面显示器和移动设备浏览器。


### 3.3 数据埋点与统计

*   **数据埋点目的：**
    *   **用户行为分析：** 了解用户如何使用系统，包括功能点击、页面停留时间、操作路径等。
    *   **功能使用统计：** 统计各核心功能（如平面图上传、设备拖拽、设备配置、报警处理）的使用频率和用户数。
    *   **性能监控：** 收集前端性能数据，如页面加载时间、API响应时间等。
    *   **业务运营监控：** 监控设备在线率、报警发生频率、报警处理及时性等业务关键指标。
*   **关键指标：**
    *   用户活跃度（DAU/MAU）
    *   新用户注册数
    *   平面图上传成功率
    *   设备添加成功率
    *   设备在线率
    *   报警数量及处理时长
    *   各功能模块使用时长和频率
*   **数据分析工具：** 优先考虑集成第三方成熟的数据分析平台（如Google Analytics, 百度统计, 或私有化部署的ClickHouse + Grafana等），具体待技术选型后确定。

### 3.4 风险与限制

*   **技术风险：**
    *   **数据源接入复杂性：** 不同设备的数据接口标准不一，可能增加数据接入的开发难度和时间成本。
    *   **实时性挑战：** 大量设备数据实时传输和处理可能对系统性能和架构设计提出较高要求。
    *   **前端渲染性能：** 在复杂平面图上渲染大量设备图标和实时数据，可能面临前端性能瓶颈。
*   **资源限制：**
    *   **开发人力：** 确保有足够的前端、后端、测试人力投入，以保证项目按时高质量完成。
    *   **服务器资源：** 随着设备数量和数据量的增长，需要持续投入服务器和带宽资源。
*   **市场风险：**
    *   **竞品竞争：** 市场上可能存在类似的可视化管理系统，需要持续关注竞品动态，保持产品竞争力。
    *   **用户接受度：** 新系统的推广和用户习惯的培养需要一定时间。
*   **时间限制：**
    *   项目开发周期可能受限于技术复杂度和需求变更，需合理规划迭代。
